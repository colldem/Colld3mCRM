{% translate 'Sistemos paskirtis' %}

CRM skirta bendrame registre tvarkyti kontaktinius asmenis ir įmones, jų ryšius, bendravimo istoriją, failus ir priminimus. Programa veikia naršyklėje, o duomenis saugo UGREEN NAS esančiuose Docker tomuose.

{% translate 'Technologijos' %}

CRM{{ crm_version|default:"—" }}
Python3.13.15
Django5.2.17
PostgreSQL17.11
Gunicorn26.2.0
Tailscale1.102.2

Papildomai: django-axes (prisijungimų ribojimas), argon2-cffi (slaptažodžių maiša), psycopg 3 (PostgreSQL), whitenoise (statiniai failai), openpyxl (XLSX importas), mozilla-django-oidc (Microsoft Entra prisijungimas). Sąsaja - AdminLTE 4 ir Bootstrap 5, įdiegti vietoje; grafikai - rankomis generuojamas SVG be išorinių bibliotekų.

{% translate 'Svarbu' %}

CRM nėra vienas perkeliamas duomenų failas. Duomenų bazė, įkelti failai, Tailscale būsena ir konfigūracija saugomi atskirose NAS katalogo vietose. Kopijuojant sistemą būtina įtraukti visas šias dalis.

{% elif documentation_topic == "installation" %}
{% translate 'Išoriniam diegėjui' %}

{% translate 'Diegimas naujame įrenginyje' %}

Procedūra skirta Linux arba NAS įrenginiui, kuriame veikia Docker Engine ir Docker Compose papildinys.

1. Paruoškite aplinką

  • Docker Engine su veikiančia komanda docker compose.
  • Prieiga prie projekto šaltinio: https://github.com/colldem/Colld3mCRM.git.
  • Tailscale paskyra ir tailnet, jei CRM bus pasiekiama per Tailscale HTTPS.
  • Rašymo teisė projekto kataloge nuolatiniams runtime duomenims.

2. Atsisiųskite ir sukonfigūruokite

git clone https://github.com/colldem/Colld3mCRM.git CRM
cd CRM
cp .env.example .env

Faile .env pakeiskite visas pavyzdines reikšmes. Slaptų reikšmių nekelkite į Git.

El. paštas, gaunami laiškai ir Entra prisijungimas konfigūruojami Nustatymų languose (žr. „Dirbti su CRM"). Vienintelis su jais susijęs .env kintamasis yra CRM_SECRETS_KEY — Fernet raktas, kuriuo šifruojami Nustatymuose suvesti slaptažodžiai. Sugeneruokite jį vieną kartą: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())". Be jo neslapti laukai veikia, bet slaptažodžių išsaugoti negalima. EMAIL_*, IMAP_*, OIDC_* .env reikšmės lieka kaip atsarginė konfigūracija (žr. .env.example).

3. Patikrinkite ir paleiskite

docker compose config --quiet
docker compose build --pull
docker compose up -d
docker compose ps

Turi veikti: crm-db, crm-tailscale, crm-web, crm-worker (foniniai priminimų ir laiškų darbai) ir crm-backup (kasdienės kopijos). Parengties patikra:

curl -fsS http://127.0.0.1:18081/health/live
curl -fsS http://127.0.0.1:18081/health/ready

4. Sukurkite pirmą administratorių

  1. Atidarykite https://<tailscale-vardas>/setup/.
  2. Įveskite CRM_SETUP_TOKEN, naudotojo vardą ir saugų slaptažodį.
  3. Prisijunkite per /login/.
  4. Ištrinkite CRM_SETUP_TOKEN reikšmę iš .env.
  5. Perkraukite žiniatinklio paslaugą: docker compose up -d crm-web.
  6. Tailscale valdymo puslapyje atšaukite panaudotą TS_AUTHKEY.
Vieša prieiga

deploy/tailscale/serve.json leidžia Tailscale Funnel. Įjungus Funnel, prisijungimo puslapis tampa pasiekiamas internete. Jei vieša prieiga nereikalinga, išjunkite Funnel ir palikite tik savo tailnet prieigą.

{% translate 'Kontakto kortelė' %}

  • Paspaudus telefono numerį naudojamas callto:, el. paštą - mailto:, URL atidaromas naujame skirtuke.
  • Dukart spustelėjus konkretų rekvizitą atidaromas tik to lauko redagavimas. Išsaugojus atnaujinamas asmuo arba jo telefono, el. pašto, adreso ir URL įrašai.
  • Dukart spustelėjus kategorijas, žymas ar įmones atidaromas atitinkamas pasirinkimas. Galima susieti kelias įmones ir sukurti naują įmonę tame pačiame valdiklyje.
  • Pridėti įrašą sukuria tik šio kontakto bendravimo istorijos įrašą. Prisegti failai sukuriami kaip įrašo priedai.
  • Pridėti priminimą išsaugo tekstą, datą ir laiką. Aktyvūs priminimai rodomi kortelėje.
  • Archyvuoti atlieka minkštą ištrynimą. Kontaktą galima atkurti Archyve.

{% translate 'Įmonių sąrašas ir kortelė' %}

  • Sąrašo filtrai, stulpeliai, Mano filtrai, rikiavimas, kategorijų ir žymų redagavimas veikia taip pat kaip kontaktuose.
  • Įmonės kortelėje rekvizitai redaguojami dukart spustelėjus konkretų lauką.
  • Susieti kontaktai skaito aktyvius PersonCompanyLink ryšius.
  • Istorijoje rodoma pati įmonė ir visų prie jos susietų aktyvių kontaktų bendravimo istorija.
  • Naujas įmonės istorijos įrašas priklauso įmonei. Jis automatiškai netampa atskiru kontakto įrašu.

{% translate 'Darbastalis ir analitika' %}

  • Darbastalis (pradinis langas) viršuje rodo keturias suvestinės korteles — kontaktų ir įmonių skaičių su pokyčiu per 30 d., jūsų šios savaitės veiklas ir vėluojančius priminimus; kiekvienoje mažas 30 dienų tendencijos grafikas, ir kiekviena veda į atitinkamą sąrašą. Žemiau: šio mėnesio veiklos pagal tipą (žiedas su procentais), nauji kontaktai ir įmonės per 6 mėnesius (stulpeliai), artimiausi priminimai su skirtukais Artimiausi / Šiandien / Rytoj (vėluojančių data raudona), bei paskutiniai kontaktai, įmonės ir įrašai. Nieko neįrašo.
  • Analitika → Ryšių priežiūra grupuoja kontaktus, kuriems reikia dėmesio: nutilę 30 / 60 / 90 d., niekada nebendrauta, be atsakingo, be telefono ir el. pašto. Kiekvieną grupę galima atsisiųsti CSV.
  • Analitika → Komunikacija / Priminimų vykdymas / Bazė ir augimas rodo veiklų, priminimų ir bazės augimo statistiką su SVG grafikais. Periodą galima keisti (30 / 90 / 365 d.).
  • Analitika → Sistemos naudojimas (tik administratoriui) suveda prisijungimus, importus, eksportus ir veiksmus pagal naudotoją iš žurnalo.
  • Visi analitikos skaičiai apriboti pagal naudotojo įrašų matomumą (sava / komandos / visi).

{% elif documentation_topic == "user" %}
{% translate 'Kasdienis darbas' %}

{% translate 'Naudotojo instrukcija' %}

Trumpi darbo scenarijai naudotojui, kuris tvarko kontaktus, įmones, istoriją ir priminimus.

{% translate 'Sukurti kontaktą' %}

  1. Kontaktų lange spauskite Pridėti kontaktą.
  2. Pasirinkite Asmuo.
  3. Įrašykite vardą, pavardę ir kitus žinomus duomenis. Kelias telefono, el. pašto, adreso ar URL reikšmes rašykite atskirose eilutėse.
  4. Parinkite iki 3 kategorijų ir iki 3 žymų.
  5. Susiekite vieną ar kelias esamas įmones. Jei įmonės nėra, ją galima greitai sukurti įmonių pasirinkimo valdiklyje.
  6. Išsaugokite. Jei sistema rodo galimą dublikatą, pirmiausia atidarykite ir patikrinkite esamą įrašą.

{% translate 'Užregistruoti bendravimą' %}

  1. Atidarykite kontakto arba įmonės kortelę.
  2. Dešinėje pasirinkite įrašo tipą: pastaba, skambutis, el. laiškas, susitikimas arba užduotis.
  3. Įrašykite tekstą. Jei reikia, pridėkite failus arba nuotraukas.
  4. Išsaugokite ir patikrinkite, ar įrašas atsirado istorijos viršuje.
Įmonės istorija

Įmonės kortelė rodo įmonės ir visų susietų kontaktų istoriją. Kontakto kortelė rodo tik konkretaus kontakto istoriją.

{% translate 'Sukurti ir užbaigti priminimą' %}

  1. Kontakto kortelėje įrašykite priminimo tekstą, datą ir laiką.
  2. Atėjus laikui, viršuje suaktyvėja varpelis ir parodo neperskaitytų priminimų skaičių.
  3. Atidarykite Priminimų langą, kad peržiūrėtumėte aktyvius ir suplanuotus.
  4. Baigtą veiksmą pažymėkite Užbaigti. Redaguojant datą priminimas vėl tampa neperskaitytas.

{% translate 'Rasti ir grupuoti įrašus' %}

  • Viršutinė paieška ieško pagal visus svarbiausius tekstinius kontaktų laukus.
  • Filtruose vieną kartą spauskite Kategorijų arba Žymų lauką ir pasirinkite kelias reikšmes.
  • Mano filtrai išsaugo dažnai naudojamą filtrų rinkinį tik jūsų naudotojui.
  • Žvaigždute pažymėkite svarbiausius kontaktus, tada filtruokite tik mėgstamus.
  • Stulpelio pavadinime pasirinkite rikiavimo kryptį arba rikiavimą pagal ID.

{% translate 'Importuoti kontaktus' %}

  1. Atidarykite Importas / eksportas.
  2. Pasirinkite UTF-8 CSV arba XLSX failą iki 10 MB.
  3. Naudokite pateiktus stulpelių pavadinimus. Kelias reikšmes viename langelyje atskirkite kabliataškiu.
  4. Importuokite ir perskaitykite sukurtų, atnaujintų bei praleistų įrašų suvestinę.
  5. Patikrinkite kelis įrašus CRM sąraše ir jų kortelėse.

Importas pirmiausia ieško sutampančio pagrindinio el. pašto, po to vardo ir pavardės. Radęs atitikmenį atnaujina esamą kontaktą. Įmonių atskiro importo šioje versijoje nėra.

{% elif documentation_topic == "admin" %}
{% translate 'Sistemos priežiūra' %}

{% translate 'Administratoriaus instrukcija' %}

Veiksmai atliekami projekto kataloge, kuriame yra compose.yaml.

Prieigos modelis

Kiekvienas CRM naudotojas turi rolę: Administratorius, Naudotojas (visi įrašai) arba Naudotojas (tik savi įrašai). Rolė ir įrašų matomumas (visi / komandos / savi) nustatomi Nustatymai → Naudotojai. Ką gali kiekviena ne-administratoriaus rolė (importas, eksportas, archyvavimas, dublikatų sujungimas, masiniai veiksmai, atsakingo keitimas, dinaminiai laukai, klasifikatoriai, žurnalas) keičiama Nustatymai → Rolės ir teisės. Django /admin/ langas atskirai reikalauja is_staff.

{% translate 'Naudotojų valdymas' %}

  1. Prisijunkite administratoriaus paskyra.
  2. Atidarykite Nustatymai → Naudotojai.
  3. Įveskite naudotojo vardą, el. paštą, vardą, pavardę, rolę, matomumą ir pradinį slaptažodį (bent 12 simbolių).
  4. Prie esamo naudotojo galima keisti rolę ir matomumą, įjungti/išjungti paskyrą arba atstatyti slaptažodį. Naudotojai netrinami, kad išliktų autorystė ir istorija.
  5. Komandas kurkite Nustatymai → Komandos ir priskirkite narius, jei naudojate „tik komandos įrašai" matomumą.

Django /admin/ reikalingas tik retiems techniniams veiksmams. Staff statusą įjunkite tik jį atliekančiam naudotojui; Superuser - tik sistemos administratoriui.

{% translate 'Slaptažodžiai' %}

Naudotojas savo slaptažodį keičia pats Nustatymai → Profilis. Administratorius pradinį arba pamirštą slaptažodį atstato Nustatymai → Naudotojai (mygtukas „Atstatyti slaptažodį"). Komandinė alternatyva:

docker compose exec crm-web python manage.py changepassword USERNAME

CRM neturi el. paštu siunčiamo slaptažodžio atkūrimo lango.

{% translate 'Nuimti prisijungimo blokavimą' %}

Po 5 nesėkmingų bandymų naudotojo ir IP pora blokuojama 30 minučių. Konkretaus naudotojo bandymus galima išvalyti:

docker compose exec crm-web python manage.py axes_reset_username USERNAME

{% translate 'Žymos, kategorijos ir dublikatai' %}

  • Nustatymai - Žymos: kurkite, pervadinkite ir parinkite spalvą. Naudojimo skaičius padeda įvertinti pakeitimo poveikį.
  • Nustatymai - Kategorijos: kurkite ir pervadinkite bendras kategorijas.
  • Nustatymai - Dublikatų tikrinimas: įjunkite arba išjunkite tikrinimą ir pasirinkite Griežtą, Standartinį arba Laisvą lygį.
  • Dublikatų sąraše pirmiausia atidarykite ir palyginkite abi korteles. Tada spauskite Palikti šį kontaktą arba Palikti šią įmonę prie įrašo, kuris turi likti aktyvus. Kitas įrašas bus sujungtas ir archyvuotas.

{% translate 'El. pašto pranešimai' %}

Nustatymai → Pranešimai (administratoriui): bendras jungiklis, numatytas santraukos laikas, įspėjimo laikas prieš įvykį, SMTP serverio laukai (serveris, prievadas, naudotojas, slaptažodis, TLS/SSL, siuntėjas, CRM adresas nuorodoms) ir „Siųsti bandomąjį laišką". Slaptažodis saugomas užšifruotas (CRM_SECRETS_KEY). Kol SMTP serveris neįvestas, laiškai tik rašomi į konteinerio žurnalą.

Siunčiami trys tipai: artėjantis įvykis, kasdienė rytinė santrauka (vėluojantys išskirti raudonai) ir „jums priskirta užduotis". Naudotojas savo santraukos laiką, įspėjimo laiką ir santraukos įjungimą keičia profilyje; laiško apačioje yra „atsisakyti" nuoroda. Periodinį siuntimą vykdo atskira crm-worker paslauga (ciklas kas WORKER_INTERVAL_SECONDS, numatyta 300 s): manage.py extend_recurrences, send_notifications ir fetch_mail. Kol jungiklis išjungtas, komandos nieko nesiunčia.

{% translate 'Gauti laiškai' %}

Nustatymai → Gauti laiškai (administratoriui): IMAP serverio laukai ir „Tikrinti dėžutę" jungiklis, o žemiau — laiškai iš CRM dėžutės, kurių nepavyko automatiškai susieti su kontaktu. Kiekvieną galima priskirti kontaktui (pagal ID, el. paštą arba vardą pavardę) — tada sukuriamas „el. laiškas" tipo istorijos įrašas — arba paslėpti. IMAP slaptažodis saugomas užšifruotas.

crm-worker periodiškai skaito neskaitytus laiškus: jei gavėjų (To/Cc) tarpe randamas žinomas kontaktas, laiškas įrašomas į jo istoriją; kitu atveju patenka į „Gauti laiškai" sąrašą. Laiškai atpažįstami pagal Message-ID, todėl kartojami nedubliuojami. Kol jungiklis išjungtas, dėžutė netikrinama.

{% translate 'Prisijungti su Microsoft' %}

Nustatymai → Prisijungimas (administratoriui): „Leisti prisijungti per Microsoft Entra ID" jungiklis, katalogo (tenant) ID, programos (client) ID, kliento paslaptis (saugoma užšifruota) ir „kurti naujus naudotojus automatiškai". Įjungus, prisijungimo puslapyje atsiranda „Prisijungti su Microsoft"; keitimai įsigalioja iškart, be konteinerio perkrovimo.

Naudotojas susiejamas pagal el. paštą su jau esančia aktyvia CRM paskyra. Naujos paskyros nekuriamos, nebent įjungtas atitinkamas jungiklis. Entra programoje nustatykite peradresavimo URI, kurį rodo tas pats Nustatymų langas (https://<adresas>/oidc/callback/). Vietinis naudotojo vardas ir slaptažodis toliau veikia.

{% translate 'Automatika' %}

Nustatymai → Automatika (administratoriui): taisyklės „kai X → daryk Y", vertinamos crm-worker kas ~5 min. Bendras jungiklis „Automatika įjungta"; kiekviena nauja taisyklė sukuriama sustabdyta ir įjungiama sąraše.

Sąlygos: kontaktas be atsakingo ilgiau nei N dienų; su kontaktu (turinčiu atsakingą) nebendrauta N dienų; su nauju kontaktu nebendrauta N dienų; priminimas vėluoja N dienų. Veiksmai: pranešti naudotojui el. paštu, priskirti atsakingą, sukurti užduotį (tekste {vardas} pakeičiamas kontaktu), pridėti žymą. Kiekviena taisyklė nepakartoja veiksmo tam pačiam įrašui dažniau nei kas N dienų (žr. „Automatikos žurnalą"). Riba — 200 veiksmų vienai taisyklei per vieną paleidimą. Įjungus, taisyklė pirmą kartą suveiks visiems tinkantiems įrašams (skaičius rodomas sąrašo stulpelyje „Dabar tinka").

REST API

Nustatymai → Integracijos (administratoriui): sukuriami API raktai kitiems įrankiams (sinchronizacijai, ataskaitoms, svetainės formoms). Raktas rodomas vieną kartą; DB saugoma tik jo sha256 santrauka. Raktas veikia su jį sukūrusio naudotojo teisėmis ir įrašų matomumu; „Tik skaityti" raktas negali keisti duomenų.

Bazinis adresas /api/v1/, autentifikacija antrašte Authorization: Bearer <raktas>, kūnas — JSON. Endpoint'ai: GET/POST /contacts, GET/PATCH/DELETE /contacts/<id> (DELETE = archyvas), tie patys /companies, GET/POST /activities, GET/POST /reminders, GET /me. Sąrašai: ?limit (≤100) / ?offset, X-Total-Count antraštė, filtrai ?q=, ?updated_since=. Kuriant kontaktą tikrinami dublikatai (jei įjungta) — atsakymas 409 su radiniais; apeiti su ?force=1. Kiekvienas keitimas žymimas žurnale (via: api). Dažnio ribojimo nėra (tailnet vidinis).

Webhooks (ten pat, Nustatymai → Integracijos): CRM POST’ina JSON į jūsų adresą įvykus pasirinktam įvykiui — contact/company.created|updated|archived, activity.created, reminder.created|completed. Kūnas {"event", "occurred_at", "data"}; antraštė X-CRM-Signature: sha256=HMAC(paslaptis, kūnas) (paslaptis rodoma vieną kartą, DB šifruota). Siunčia crm-worker: 10 s timeout, kartojimas su didėjančiu intervalu (iki 6 kartų), po ilgos klaidų serijos webhook automatiškai išjungiamas. „Bandyti" siunčia ping iškart. Masinis archyvavimas webhookų per įrašą nesiunčia (pavienis — siunčia).

{% translate 'Atnaujinti programą' %}

Įprastai — per CI/CD: kiekvienas git push į main paleidžia patikras (GitHub Actions „CI": ruff, testai, Docker image). Diegimas — pažymėjus versijos žymą:

  1. git tag v0.52.0 && git push origin v0.52.0
  2. GitHub → Actions → „Deploy" — verify job'as pakartoja patikras.
  3. Production environment praleidžia tik v* formos žymas. Patvirtinimo mygtuko nėra — „Required reviewers" privačiame saugykloje reikalauja mokamo GitHub plano, todėl sąmoningas veiksmas yra pati žymos įkėlimas, kurią atlikti gali tik saugyklos savininkas.
  4. Self-hosted runner ant NAS: DB kopija (pre-<versija>-<laikas>.dump) → šaltinio įkėlimas į /opt/crm (išsaugant .env, runtime/) → docker compose build --pull → up -d → sveikatos patikra (/health/ready).

Rankinis atsarginis kelias, jei runner neveikia: NAS'e cd /opt/crm, DB kopija, įkelti šaltinį, docker compose build --pull && docker compose up -d, patikrinti docker compose ps ir /health/ready. Runner'io sąranka — deploy/runner/README.md.

{% translate 'Aplinkos ir izoliacija' %}

Kintamasis CRM_ENVIRONMENT (numatyta production) nurodo, kuri tai aplinka. Bet kuri kita reikšmė (pvz. staging) reiškia izoliuotą kopiją — tokią, kuri paprastai atkuriama iš produkcijos kopijos ir todėl turi realius asmens duomenis bei realius prisijungimo duomenis. Tokioje aplinkoje programa priverstinai išjungia:

  • el. pašto siuntimą (SMTP) — nė vienas laiškas neišeina;
  • gaunamų laiškų tikrinimą (IMAP);
  • prisijungimą su Microsoft (Entra);
  • webhook'us — jie nei įrašomi į eilę, nei siunčiami.

Šios apsaugos gyvena aplinkos kintamajame, ne duomenų bazėje, todėl duomenų perkrovimas iš produkcijos jų neišjungia. Apačioje visuose languose (taip pat ir prisijungimo lange) rodoma raudona juosta su aplinkos pavadinimu. Papildomai komanda python manage.py sanitize_staging išvalo iš atkurtos kopijos SMTP/IMAP/Entra nustatymus, išjungia webhook'us ir pašalina API raktus; produkcijoje ji paleisti atsisako.

Veikia trys aplinkos:

  • Kūrimo — programuotojo kompiuteryje, SQLite, testiniai duomenys.
  • Staging — https://crm-staging.example.com, NAS'e, atskira duomenų bazė su produkcijos duomenų kopija. Atnaujinama automatiškai po kiekvieno pakeitimo main šakoje. Skirtingai nei produkcija, ji pasiekiama tik Tailscale tinkle — į viešą internetą neišeina.
  • Produkcija — https://crm.example.com, diegiama pažymėjus versijos žymą.

Įprasta eiga: pakeitimas → main → automatiškai atsiranda staging'e → patikrinate gyvai su realiais duomenimis → git tag vX.Y.Z → produkcija. Staging duomenis atnaujinti iš produkcijos: NAS'e paleisti sh /opt/crm-staging/scripts/refresh-staging.sh (pridėjus --with-media nukopijuojami ir prisegti failai). Skriptas produkcijos nekeičia — iš jos tik nuskaito kopiją.

{% translate 'Pagrindiniai duomenų objektai' %}

{% translate 'Įjungtos apsaugos' %}

  • Visi CRM duomenų langai reikalauja prisijungimo.
  • Slaptažodžiai maišomi Argon2 algoritmu ir turi būti bent 12 simbolių.
  • Po 5 nesėkmingų prisijungimų taikomas 30 minučių blokavimas pagal naudotoją ir IP.
  • Naudojama CSRF apsauga, HttpOnly ir SameSite=Lax sesijos slapukai.
  • Išorinėje aplinkoje įjungus DJANGO_FORCE_HTTPS=true naudojami saugūs slapukai ir HSTS.
  • Failų atsisiuntimas reikalauja autentifikacijos ir tikrina, ar susijęs įrašas nėra archyvuotas.
  • Nustatymuose suvesti integracijų slaptažodžiai (SMTP, IMAP, Entra) duomenų bazėje saugomi užšifruoti; raktas CRM_SECRETS_KEY laikomas tik .env, todėl DB kopijose ir eksporte lieka tik neskaitomas šifruotas tekstas.
  • Konteineriai paleidžiami su no-new-privileges, CRM programa veikia ne root naudotoju.

{% translate 'Žinomos ribos' %}

  • Teisės valdomos rolės lygiu (trys rolės + teisių lentelė), o ne kiekvienam naudotojui atskirai.
  • Įrašų matomumas yra „visi / komandos / savi", bet visi matomi įrašai yra ir redaguojami - nėra tik skaitymo prieigos.
  • Nėra el. paštu siunčiamo slaptažodžio atkūrimo (kaip alternatyva galimas Microsoft Entra prisijungimas).
  • Kartojami priminimai kuriami iš anksto kaip atskiri įrašai iki ~400 d. arba 200 kartojimų.
  • Nėra atskiro įmonių CSV arba XLSX importo.
  • Sujungiant skirtingas užpildytas to paties rekvizito reikšmes paliekama pasirinkto pagrindinio įrašo reikšmė. Jei bendras žymų arba kategorijų skaičius viršija 3, prieš sujungimą reikia rankiniu būdu sumažinti pasirinkimus.
  • Nėra programoje valdomo atsarginių kopijų šifravimo ar automatinio atkūrimo testo.
  • Tailscale Funnel atveju prisijungimo puslapis pasiekiamas viešame internete.

{% translate 'Atsarginės kopijos ir atkūrimas' %}

Kopija laikoma patikima tik tada, kai jos atkūrimas patikrintas atskiroje saugioje aplinkoje.

Prieš atkūrimą

Atkūrimas perrašo duomenų bazę ir gali perrašyti failus. Pirmiausia sustabdykite CRM, padarykite dabartinės būsenos kopiją ir įsitikinkite, kad pasirinktas teisingas Compose projektas.

{% translate 'Sukurti kopiją' %}

Sukurkite backups katalogą projekto viduje ir vykdykite:

mkdir -p backups
docker compose exec -T crm-db pg_dump -U crm -d crm -Fc > backups/crm.dump
tar -czf backups/crm-media.tgz runtime/media
cp .env backups/env.confidential

Atskirai nukopijuokite runtime/tailscale-state, compose.yaml ir deploy/tailscale/serve.json. Kopijos katalogas turi būti apsaugotas kaip ir pati CRM.

{% translate 'Patikrinti kopiją prieš saugojimą' %}

test -s backups/crm.dump
tar -tzf backups/crm-media.tgz
docker compose exec -T crm-db pg_restore --list < backups/crm.dump

Užrašykite kopijos datą, CRM versiją, failų dydžius ir patikros rezultatą. Vien failo egzistavimas neįrodo, kad duomenis galima atkurti.

{% translate 'Atkurti duomenų bazę' %}

  1. Sustabdykite žiniatinklio paslaugą: docker compose stop crm-web.
  2. Padarykite dabartinės būsenos kopiją.
  3. Atkurkite į tuščią crm duomenų bazę:
docker compose exec -T crm-db dropdb -U crm --if-exists crm
docker compose exec -T crm-db createdb -U crm crm
docker compose exec -T crm-db pg_restore -U crm -d crm --no-owner < backups/crm.dump

Failus atkurkite į runtime/media tik iš patikrintos, su ta pačia duomenų bazės kopija sukurtos archyvo versijos.

{% translate 'Atkūrimo patikra' %}

  1. Paleiskite docker compose up -d ir patikrinkite, kad visos paslaugos yra healthy.
  2. Patikrinkite /health/live ir /health/ready.
  3. Prisijunkite bandomuoju naudotoju.
  4. Palyginkite kontaktų, įmonių, istorijos įrašų ir priminimų skaičius su kopijos suvestine.
  5. Atidarykite bent vieną kontakto ir įmonės kortelę.
  6. Atsisiųskite bent vieną seną priedą ir įkelkite naują bandomąjį failą.
  7. Sukurkite, pakeiskite ir iš naujo atidarykite bandomą kontaktą.
  8. Užfiksuokite datą, vykdytoją ir rezultatą. Tik sėkmingai praėjusi kopija laikoma tinkama atkūrimui.
